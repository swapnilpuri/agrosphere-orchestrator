# Quality policy configuration

Policies use safe YAML and strict Pydantic validation. Set AEO_QUALITY_POLICY to a milestone-specific file and AEO_GOVERNANCE_APPROVERS to canonical Windows SID identities as an administrator. Review the full file, then run aeo quality activate --milestone ID. Activation authenticates with the existing WindowsConsoleHumanVerifier; version changes require another authenticated activation. Editing a live policy silently blocks validation and readiness. Do not activate the supplied template unchanged: its symbolic validators deliberately have no installed or allowlisted tools and its acceptance mappings are empty.

Each gate includes ID, type, repository, milestone/task scopes, input paths, command/evaluator, expected exit, severity, blocking flag, timeout, retry permission, explicit skip permission, validator version, format and configuration. The persisted policy digest binds every result. Repository.validators maps symbolic names to IDs in the existing ExecutionPolicy.validation_commands. No repository can supply executable argv. A command is an argv list, never a shell string. Validator wrappers must already be installed and trusted; no downloads or installation happen here.

Supported reusable adapters: exit status for builds/lint/type checks/infrastructure/database commands; JUnit XML on stdout for named test cases; coverage.py JSON on stdout for measured coverage; structured JSON or SARIF 2.1.0 on stdout for mature scanners; file/source validation for mandatory documents; explicit lexical architecture rules. JSON reports must include validator_version, findings and optionally test_cases with passed/failed/skipped statuses. Coverage requires totals.percent_covered. Malformed output, missing tool/version, truncation or timeout cannot pass. Gate.validator_version for exit/JUnit is an administrator declaration; structured scanner versions are checked against report metadata. Raw redacted outputs, argv, configuration and normalized results are content-addressed in SQLite.

Technology adapters are command-driven: Java Maven build/unit/integration/static/coverage/dependency checks; Python pytest/Ruff/types/coverage/dependencies; Angular build/unit/ESLint/types/dependencies; Dockerfile lint/Compose/infrastructure/container checks; database migration/SQL/schema checks. The validator catalog names these capabilities. Configure actual commands appropriate to each repository. For Java or Angular coverage export a trusted wrapper report in the documented coverage format. Native scan output can be converted by an administrator-owned wrapper to JSON/SARIF; the orchestrator never invents findings.

The default native validator denies network and repository writes. Builds/test suites that need generated files must use explicitly granted AEO-2 isolated worktrees and purpose-scoped validation commands; the standalone AEO-4 runner remains read-only. It does not automatically rerun write-capable builds or copy source into new worktrees. Missing access or unsupported sandbox capability blocks validation. No live model is invoked by a gate.

Criterion IDs are AC-1, AC-2 in approved requirement order. Each mapping repeats exact approved criterion text, requirement ID, implementing task, gate and exact test case. Unmapped, skipped or absent tests remain NOT_EVALUATED; executing a suite alone proves no business criterion. Critical scenarios are enforced as explicit required criterion mappings and suites as mandatory gates. Human procedures use human: true and an artifact-bound DELIVERY_APPROVAL action criterion:REQ-ID:AC-N; record the procedure in the request justification. A human criterion approval cannot approve delivery itself.

Architecture rules enforce required/prohibited files, required/prohibited literal dependency tokens, approved file hashes, database ownership and stack markers. These checks establish only their declared lexical properties; use mature compatibility tools for semantic OpenAPI/event/schema differences. Gate inputs identify approved contracts and ADRs. Material failures create architecture.review evidence and block delivery; revise design, authenticate approval and revalidate. A privileged exception never silently overrides an architecture failure.

Documentation gates require exact repository-relative paths. Include overview, requirements, architecture, plan, acceptance criteria, relevant ADRs, editable C4/sequence diagrams, service design and as-built notes per milestone. File presence/source structure is distinct from rendering: configure a separate allowlisted PlantUML gate for required rendering. Existing AEO-1C approved design files are checked independently. Full repository snapshots bind documentation evidence to exact Git HEAD and content hash.

Legacy milestone scheduling state remains compatible. AEO-4 is adopted through explicit policy activation; legacy milestones without an activated policy retain AEO-1C delivery behavior. Once activated, the old approve-delivery route calls the same governance guard and consumes its one-time approval atomically. Activation history cannot be deleted through supported APIs. Readiness for a milestone without an active policy is always BLOCKED. Migrate every delivery milestone to AEO-4 before relying on it as an organization-wide gate.

Use evaluator: execution with a command ID to import deterministic AEO-2 validation output from a separately granted write-capable execution. New AEO-2 results store validated_artifact_hash. AEO-4 requires the same current whole-tree hash, worktree root and exact command argv; older results without this hash block rather than being trusted. This supports builds that need generated outputs without broadening standalone gate permissions.

ValidationCommand.read_paths is an administrator-owned list of explicit absolute runtime/tool paths (for example the project virtual environment and installed Python base prefix). Root directories, user home/ancestors and known credential directories are rejected. These paths are read-only in the command sandbox and are policy/context-bound; they are not added to model execution permissions. Grant only the runtime files a validator needs.
