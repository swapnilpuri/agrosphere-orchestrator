# Approval engine

AEO-4 extends existing DesignDecision records, HumanVerifier and WindowsConsoleHumanVerifier. It does not add a second identity authority. Approval requests are append-only governance events and decisions use governance.CATEGORY kinds in the existing design decision table. Categories cover design, architecture, breaking contracts, security/dependency exceptions, privileged execution, delivery and deployment. Category records confer no implicit execution or deployment capability; original execution grants and design decisions remain mandatory at their original boundaries.

The CLI prints the exact request (project, milestone, action, requesting agent, repository roots/revisions, design/scope/policy digests and expiration) before authentication. The human confirms the request/digest and decision, then Windows LogonUser resolves a canonical SID. An arbitrary --actor parameter is never accepted. Empty approver configuration fails closed. Trusted verifier injection exists for deterministic tests and future identity adapters; untrusted callers cannot supply verifiers across a network because no network approval API exists.

Approvals are checked again inside BEGIN IMMEDIATE after authentication. Expiration, approver membership, exact artifact context and latest decision are mandatory. Agent self-approval, rejection retry, revocation retry, action/category mismatch and replay of consumed one-time authorization fail closed. A rejected request requires revised artifacts or policy before re-request. Revocation is append-only. Delivery authorization is consumed within the old delivery transaction; reports distinguish READY_FOR_APPROVAL from APPROVED_FOR_DELIVERY. No action merges, pushes or deploys.

Authentication limitations: this is an interactive local Windows development interface, requiring a password rather than Windows Hello PIN. It is not remote SSO/MFA, tamper-proof hardware authorization, or production-grade identity verification. Local administrators can alter code/database/config and remain trusted. Keep identity credentials outside model prompts and runtime; credentials are neither stored nor emitted by the verifier.
