# Quality, security and approval engine design

A trusted administrator configures typed quality policies and execution command IDs. Repository manifests may map validator names to administrator-allowlisted commands. Policies are registered by an authenticated human and are immutable by digest. A milestone must explicitly select an activated policy; no gates or missing evidence means blocked. Policy replacement invalidates prior readiness and approvals.

A gate interface receives a bounded repository snapshot and produces structured deterministic evidence. Shell-free native sandbox validation reuses Codex permission profiles and process management. Network and application writes are denied by default. Builds requiring writes must be run through an explicitly granted isolated AEO-2 execution; AEO-4 can consume its exact deterministic evidence. Scanner reports are never accepted from LLM prose. Canonical JSON output, JUnit, coverage and SARIF adapters retain raw redacted reports and normalized findings. Missing tools, unsupported formats and truncated output fail closed.

A whole-worktree hash plus Git HEAD binds evidence, approved design revision, scope, policy and delivery authorization. Evidence payloads live content-addressed in SQLite with update/delete guards. Freshness, digest integrity and current artifacts are rechecked at readiness, human decision and one-time action consumption. Local database/config/code administrators remain trusted. Windows password authentication is a local development boundary; verifier adapters are trusted dependency injection, not remotely authenticated identity.

Acceptance mappings name approved requirement/criterion text (stable indexed criterion IDs), implementing task and exact deterministic test case or human procedure. An absent mapping remains not evaluated. Human procedures require their own exact artifact-bound decision. Coverage is separately evaluated and cannot verify business criteria by itself.

Quality, security, architecture, contracts and documentation gates block by policy. High and critical security findings always block unless a narrowly scoped, expiring human exception is recorded. Medium treatment is configurable; low findings remain visible. Architecture deviations generate review requests and require design revision/revalidation. Agent reviews remain advisory. Independent review tasks use existing role registry and dependency scheduler; no agent self-approval.

Task quality_state records IMPLEMENTED → VALIDATING → QUALITY_REVIEW → SECURITY_REVIEW → READY_FOR_DELIVERY_REVIEW → AWAITING_DELIVERY_APPROVAL → DELIVERY_APPROVED. It augments legacy scheduling state. Failed retry-eligible gates feed the existing bounded repair evidence; write recovery still requires a fresh execution grant. No automatic delivery, merge or deployment is introduced.
