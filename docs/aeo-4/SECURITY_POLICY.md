# Security governance configuration

Configure established scanners as trusted allowlisted commands: secret scanners, dependency vulnerability scanners, SAST, container scanners and configuration auditors. No custom vulnerability database or credential detector is implemented. High/Critical findings block by default; Medium blocks unless the activated policy says otherwise; Low/Informational remain visible. SARIF security-severity scores preserve Critical/High treatment. In-source suppression declarations are retained in raw evidence but never automatically suppress findings.

Add explicit configuration audit/security design gates covering Keycloak client/realm policies, JWT signature/issuer/audience and OIDC validation, API Gateway routes and authorization, service identity/TLS, MQTT broker authentication/ACLs, RabbitMQ virtual-host permissions, database credentials and public port exposure. Scanner configuration and versions are policy-bound evidence. These domain checks must be configured for the affected repositories; no unexecuted scanner or absent validator is reported as passed. Changes to these controls should also be protected by required architecture approved-hash rules or external semantic configuration checks, yielding an architecture review on deviation.

An exception is an approval request with SECURITY_EXCEPTION or DEPENDENCY_EXCEPTION and exact action GATE-ID:FINDING-ID. Human verification, justification, approver, artifact/design/policy scope and expiry are mandatory. Exceptions never remove original findings. Expired/revoked decisions or modified artifacts immediately restore blocking. Scanner command failure, missing evidence and invalid reports cannot be waived as findings. No AI agent can decide exceptions. Security failures do not enter automatic repair.

The threat model trusts local code, config and database administrators. Policy files, execution allowlists and verifier implementations belong outside the model's write scope. Codex's native sandbox and process runner are reused and probed before standalone commands, with network and credentials denied by profile. No production identity or isolation certification is claimed. Existing redaction protects known credential patterns; avoid logging scanner plaintext secrets and configure scanners to redact their own sensitive output.
