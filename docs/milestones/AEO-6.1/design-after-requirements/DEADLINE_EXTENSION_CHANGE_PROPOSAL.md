# Governed minimal change proposal: authenticated same-run deadline extension

Status: unapproved separate scope; not registered, implemented or authorized by AEO-6.1. No extension command exists. Existing autonomous.py remaining() derives the deadline from original created_at plus request.limits.max_seconds and enforces wall/monotonic/persisted elapsed time. Pause/restart/setting changes do not renew it. The preserved run expired at 2026-10-26T06:28:07.706005Z. Its stored elapsed usage is a checkpoint observation, not evidence of remaining time today.

Proposed future workflow reuses the current governance category mechanism and HumanVerifier. A separately approved requirements/design/plan package must define a bounded RUN_DEADLINE_EXTENSION subject: exact run ID, immutable original request hash and deadline, current checkpoint/operation/usage digest, previously authorized effective deadline/version, requested absolute new UTC deadline, rationale and evidence, approving role/policy version, request expiry, and extension-count/cumulative cap. The authenticated operator must choose duration and caps; none are invented here. Validate exact unchanged run after authentication. Deny agent/self approval, removed SID, stale scope, unsupported version, excessive caps, replay and conflicting concurrent extensions.

Store an additive immutable grant and transactional audit through existing governance records. Keep original request, max_seconds, created_at, counters and old events unchanged. A future controller may derive effective deadline from the validated grant chain; every advance/dispatch/recovery must recheck it and all original task/invocation/cost/attempt ceilings. Revocation never deletes a grant or rewinds completed operations; it blocks future dispatch. An extension grants time only and cannot supply design/execution/quality/evidence/roadmap authority. Failed/expired decision is inert. A single serialized transaction must ensure one valid chain successor. No new run or alternate controller.

Test expiry boundary, clock movement, restart, duplicate/competing approvals, revoked/removed authority, stale checkpoint, unchanged usage, active-operation ownership and execution timeouts versus effective remaining time using disposable fixtures. Compare every original database row and active-run identity. Register this separate proposal through normal requirements -> authenticated requirements approval -> design -> validation -> authenticated design approval -> implementation-ready/plan/exact execution grants before code. This document is an approval package outline, not a request to waive current expiry.
