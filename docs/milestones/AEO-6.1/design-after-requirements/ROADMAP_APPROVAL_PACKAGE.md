# Autonomous roadmap approval package

Status: preparation only. AEO_AUTONOMOUS_ROADMAP is null. Existing narrative roadmap files are not an authenticated machine-readable dependency grant.

Recovered sources in agrosphere-architecture: docs/roadmap/MILESTONES.md, IMPLEMENTATION_BACKLOG.md, MILESTONE_1A.md, MILESTONE_1B.md, MILESTONE_1C.md and docs/milestones/reconciliation-1a-3a/ACCEPTANCE_MATRIX.md. MILESTONES.md defines broad scopes/exit gates and explicitly separates incremental authorization. Historical local delivery and engineering acceptance assessments do not establish authenticated completion. The 1B forensic/adjudication matrix retains exact provenance and uncertainty.

Existing autonomous_models.Roadmap requires {milestones:[{id,depends_on:[id,...]}]}; it rejects duplicate IDs/dependencies, unknown dependencies and cycles. ExistingServices.eligibility requires the configured roadmap path to be a hashed context reference in the exact selected milestone requirements scope. Each dependency must have a formal DesignCase state COMPLETED, fresh recovery classification COMPLETED, verified acceptance criteria and no conflicts. A YAML file alone or a configured path cannot satisfy that check.

Preparation sequence: product owner reviews the exact dependency graph for milestone 2 and all referenced incremental milestones, rather than inferring it from numbering. Resolve evidence/acceptance gaps independently. An authorized maintainer then writes the selected graph in the approved repository, captures file SHA-256 and repository HEAD, validates Roadmap, and includes that exact path/hash/HEAD in the eventual milestone 2 DesignInput context. Register milestone design 2 --requirements <validated-input>; obtain authenticated approve-requirements 2, generate/validate design and obtain approve-design 2. Configure AEO_AUTONOMOUS_ROADMAP to the exact approved path locally; retain the application manifest. The runtime rechecks the hash and dependency evidence. Changes require a new scope/approval.

No standalone roadmap-approve command exists, and no graph or dependency completion has been invented or configured here. The required owner decision is the actual dependency graph and acceptance evidence for each predecessor; the M2 performance/product choices are separately documented. Do not register a fabricated graph with empty dependencies to bypass missing completion.
